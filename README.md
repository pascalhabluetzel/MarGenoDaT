# MarGenoDaT

**MARine GENOmics DAta managemenT** – from metabarcoding pipeline output to a Darwin Core Archive for OBIS and GBIF.

## Why

Metabarcoding outputs differ by bioinformatics pipeline, are rarely well documented, often lack sampling and lab metadata, and do not map directly onto Darwin Core. MarGenoDaT provides two tools that follow the **eDNAqua-Plan** recommendations:

1. **Metadata template builder** – choose the metadata fields your project needs and download a template to fill in.
2. **`edna2dwca.py`** – combine the filled-in template with your OTU/ASV table into a validated Darwin Core Archive.

```
template builder ──► metadata.csv ─┐
                                    ├──► edna2dwca.py ──► dataset.zip + QC report ──► IPT (GBIF/OBIS)
pipeline output ──► otus.tsv ──────┘
```

## 1. Metadata template builder

`eDNA_metadata_template_builder.html` – a single file that runs offline in any browser. No installation.

**Fields (1,788 terms, definitions from the official sources):**
- Darwin Core + Humboldt extension
- MIxS 7.0.1, all checklists and environmental extensions
- GBIF/OBIS DNA-derived data extension
- FAIRe eDNA checklist v1.0.2 (requirement levels), OBIS required flags

**Usage**
1. Open the file in Chrome, Edge, Firefox or Safari.
2. Select an assay type (Metabarcoding hides qPCR/ddPCR-only fields).
3. Add fields by search, filters, or quick-add buttons (FAIRe mandatory, FAIRe highly recommended, OBIS required, MIMARKS-survey mandatory). The **i** icon shows each standard's definition, examples and allowed values.
4. Download:
   - **Metadata template** – one CSV, one row per sample, `samp_name` as key, columns in FAIRe order. Values shared by all samples are typed once and copied down.
   - **Data dictionary** – definition and source of every column.

Options: semicolon separator (European Excel), guidance rows under the header, and re-import of a downloaded template to restore a selection.

> Fields marked **auto** (`seq_id`, `dna_sequence`, `scientificName`, `occurrenceID`, `eventID`, `basisOfRecord`, `occurrenceStatus`) come from the pipeline output or are generated by `edna2dwca.py`. Remove them from the template.

## 2. edna2dwca.py

Command-line converter. Requires **Python ≥ 3.8**, standard library only – nothing to install.

```bash
# Optional: create a dataset config to fill in
python edna2dwca.py --write-config-template dataset_config.json

# Build the archive
python edna2dwca.py --otu otus.tsv --metadata metadata.csv \
                    --config dataset_config.json --fasta otus.fasta -o my_dataset
```

| Option | Content |
|---|---|
| `--otu` (required) | OTU/ASV table: ID, one column per sample, taxonomy string |
| `--metadata` (required) | Sample metadata, one row per sample (template builder output) |
| `--config` | JSON: dataset description (EML), creators, licence, primers, default values |
| `--fasta` | Representative sequences (headers = OTU IDs); fills `DNA_sequence` |
| `--min-reads` | Minimum reads for an occurrence record |
| `--unassigned keep\|drop` | Keep unassigned OTUs (as `Biota`, default) or drop them |
| `--strict` | Non-zero exit code if the QC report has errors |
| `-o` | Output name |

**Output**
- `my_dataset.zip` – Darwin Core Archive:
  - `occurrence.txt` – one record per OTU × sample with reads; `basisOfRecord = MaterialSample`; reads in `organismQuantity`, total reads per sample in `sampleSizeValue` (unit: DNA sequence reads).
  - `dna_derived_data.txt` – target gene, primers, sequencing method, reference database, sequences.
  - `meta.xml`, `eml.xml`
- `my_dataset_QC_report.md` – errors and warnings (e.g. coordinates inconsistent with water body or country, missing taxonomic ranks, inferred defaults).

**Taxonomy:** the lineage string is split into all Darwin Core rank columns (kingdom to infraspecificEpithet); the original string is kept in `verbatimIdentification`.

When the QC report shows no errors, check the archive with the [GBIF Data Validator](https://www.gbif.org/tools/data-validator) and upload it to a GBIF or OBIS IPT.

## Standards used

- [Darwin Core](https://dwc.tdwg.org/) and the [GBIF DNA-derived data extension](https://rs.gbif.org/extension/gbif/1.0/dna_derived_data_2024-07-11.xml)
- [Publishing DNA-derived data through biodiversity data platforms](https://docs.gbif.org/publishing-dna-derived-data/en/)
- [GSC MIxS](https://genomicsstandardsconsortium.github.io/mixs/), [FAIRe](https://fair-edna.github.io/), [ENVO](https://www.ebi.ac.uk/ols4/ontologies/envo)
- eDNAqua-Plan [D3.2 – Best practices for eDNA data repositories](https://zenodo.org/records/18833237) and [eDNA Data Management Plan template](https://zenodo.org/records/20714902)
